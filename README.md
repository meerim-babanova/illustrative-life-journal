# Illustrated Life Journal — Phase 1

A personal illustrated journaling app. Phase 1 delivers the app shell,
navigation, character creator, and a mock journal-generation flow — no
backend, no AI, no image generation yet (those are Phases 2–6).

## ⚠️ Important: platform folders are not included

This project was authored in an environment without the Flutter SDK, so the
native `android/` and `ios/` platform folders (normally generated by
`flutter create`) are **not** included — only `lib/`, `test/`, and
`pubspec.yaml`. Generate them in one step on your machine:

```bash
# 1. Scaffold a fresh Flutter project with the platform folders
flutter create --org com.yourcompany illustrated_life_journal_shell

# 2. Copy this project's lib/, test/, pubspec.yaml, analysis_options.yaml
#    into the freshly created project, overwriting the generated versions
cp -r lib test pubspec.yaml analysis_options.yaml illustrated_life_journal_shell/
cd illustrated_life_journal_shell

# 3. Fetch dependencies
flutter pub get

# 4. Run
flutter run
```

(If you already have a Flutter project set up, just copy `lib/`, `test/`,
`pubspec.yaml`, and `analysis_options.yaml` into it instead of step 1.)

## What's implemented

- Warm, storybook-flavored app theme (colors, typography, spacing, radii)
- Named-route navigation across the Phase 1 screen flow
- Welcome → Character Introduction → Character Studio → Home
- Character Studio with dynamic category tabs (Face, Eyes, Hair, Skin) and
  option grids driven entirely by data (`CustomizationCatalog`) — adding
  more options later doesn't require UI changes
- A live, config-driven placeholder character illustration
  (`CharacterPreview`) that updates as you customize
- Persistent character configuration via `SharedPreferences`
  (`CharacterRepository` / `CharacterProvider`)
- Home screen: greeting, character, "What happened today?" CTA, recent
  memories (empty state until you write one), Stories preview
- Basic Stories screen with mock data and an empty state
- Basic Journal Entry screen → Generation (loading) screen → Journal Page
  screen, using a `MockJournalGenerationService` (2-second simulated delay,
  no network calls) so the full write → generate → view flow works without
  any external AI service
- A smoke test (`test/app_smoke_test.dart`) verifying the app boots to
  Welcome for a first-time user

## What's intentionally NOT implemented yet

Per the spec's phased plan: Supabase auth/database (Phase 2), the real
journal/story data model and persistence (Phase 3), AI text interpretation
(Phase 4), real image generation (Phase 5), character-consistency/asset
pipeline (Phase 6), and polish/analytics/testing/deployment (Phase 7).
