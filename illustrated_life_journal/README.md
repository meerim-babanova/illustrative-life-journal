# Illustrated Life Journal — Phase 2

A personal illustrated journaling app. The user creates a persistent
character, writes free-form memories, and the app generates an illustration
of that memory featuring their character — via a small backend that keeps
the AI provider's API key server-side.

## Project layout

```
lib/            Flutter app (this is the client — no secrets live here)
test/           Flutter tests
server/         Node/Express backend — holds the AI provider API key,
                exposes POST /generate-illustration (see server/README.md)
```

## ⚠️ Platform folders are not included

This project was authored in an environment without the Flutter SDK, so the
native `android/` and `ios/` platform folders (normally generated by
`flutter create`) are **not** included — only `lib/`, `test/`, and
`pubspec.yaml`. Generate them in one step on your machine:

```bash
flutter create --org com.yourcompany illustrated_life_journal_shell
cp -r lib test pubspec.yaml analysis_options.yaml illustrated_life_journal_shell/
cd illustrated_life_journal_shell
flutter pub get
```

(If you already have a Flutter project set up, just copy `lib/`, `test/`,
`pubspec.yaml`, and `analysis_options.yaml` into it instead.)

## Running the whole thing locally

```bash
# 1. Start the backend (see server/README.md for full details)
cd server
npm install
cp .env.example .env
# either set OPENAI_API_KEY=sk-... in .env for real generation,
# or set IMAGE_PROVIDER=mock in .env to test without a key
npm start   # listens on http://localhost:8787

# 2. In another terminal, run the Flutter app (from the shell project
#    you set up above)
flutter run -d chrome
# The app defaults to http://localhost:8787 for the backend. To point at a
# different backend: flutter run -d chrome --dart-define=BACKEND_BASE_URL=https://your-backend.example.com
```

## What's implemented

**Core app (Phase 1, still intact):**
- Warm, storybook-flavored app theme; named-route navigation
- Welcome → Character Introduction → Character Studio → Home
- Character Studio with dynamic category tabs and option grids
- Persistent character configuration (`SharedPreferences`)

**Phase 2:**
- Unified `JournalEntry` model (title, text, dates, `GenerationStatus`,
  illustration URL/error) — persisted locally via `JournalRepository`
  (`SharedPreferences`), survives refresh/restart
- Write Memory screen: title + open-ended text, character count,
  validation, warm/on-brand styling (not a generic form)
- Home's "recent memories" now shows real saved entries (newest first),
  with a thumbnail/status per entry, replacing the old static empty-state
  copy once a memory exists
- Illustration generation pipeline: `JournalEntry` + `CharacterConfig` →
  `IllustrationPromptBuilder`/`CharacterPromptBuilder` → backend →
  AI provider → image URL → persisted on the entry
- `IllustrationGenerationService` abstraction — the Flutter UI never talks
  to an AI provider directly, only to this app's own backend
  (`BackendIllustrationGenerationService`, calling `server/`)
- Generation states throughout (not generated / generating / generated /
  failed), including a **regenerate** flow that keeps the previous
  successful image visible (with a small failure banner on top of it)
  if a regeneration attempt fails, rather than losing it
- Responsive layout: content is centered with a max width on wide/desktop
  viewports (`AppBreakpoints`) rather than stretching edge-to-edge
- Deterministic, fixed-height cards (`AppSizes`) for Story/Recent-Memory
  cards — fixes the earlier overflow bug (was caused by an `AspectRatio`
  cover scaling with variable card width while text below it stayed a
  roughly constant height, which meant total height could exceed the
  parent's fixed height at some viewport widths)
- Backend (`server/`): Express app, provider abstraction
  (`lib/imageProviders/`) with a real OpenAI implementation and an opt-in
  mock for local testing, input validation, no journal text in logs,
  friendly client-facing errors with technical detail logged server-side
  only

## Configuration / secrets

The only secret in this whole project is `OPENAI_API_KEY`, and it belongs
**only** in `server/.env` (gitignored) or your hosting platform's secret
manager — never in Flutter/Dart source, never in a `--dart-define`, never
shipped to the browser. See `server/README.md` for the full environment
variable list and deployment notes.
